## Example response

```json
{
  "ok": false,
  "request_id": "req_…",
  "reason": "live_stream",
  "error": {
    "code": "live_stream",
    "message": "The video is a live stream: broadcasting now, scheduled, or ended without a published recording. Live streams are not supported; retrying will not help until YouTube publishes a recording (24/7 streams never get one)."
  }
}
```

v1 failures carry `error.code` and `error.message` (plus `issues` on validation failures); transcript failures repeat the code as a top-level `reason` and add an `ai_fallback` hint.

<a id="sec-what-it-means" />

## What it means

**Live stream.** The video is a live stream: broadcasting now, scheduled, or ended without a published recording. Live streams are not supported; retrying will not help until YouTube publishes a recording (24/7 streams never get one).

Shown to end users as: “Live streams aren't supported. Once the broadcast has ended and YouTube has published the recording, the video can be fetched like any other.”

<a id="sec-why-it-happens" />

## Why it happens

- Live streams are not supported. The video is broadcasting right now, so there is no finished caption track or audio file to fetch. 24/7 streams (lofi radio, news channels, webcams) are always in this state.
- A finished live stream whose recording YouTube never published. yt-dlp reports it as "This live event has ended" or, for a 24/7 stream, "This live stream recording is not available"; nothing will ever be fetchable at that URL.
- A scheduled premiere or live event that has not started yet ("This live event will begin in ...").

<a id="sec-what-to-do" />

## What to do

- Do not retry while the stream is live: the same request fails the same way and nothing on your side changes it. Failed requests are never charged.
- Once the broadcast has ended and YouTube has published the recording (usually within minutes, sometimes hours for long streams), send the same request again: it is then an ordinary video and either its captions are served or the audio is transcribed.
- To detect this before calling, YouTube's page or Data API marks the video as live (liveBroadcastContent is "live" or "upcoming"); skip those in a pipeline and revisit them later.
- AI transcription would not help: there is no complete audio file to transcribe while the stream is running.

**Retryable?** Not while it is live. After the broadcast ends and the recording is published, the same request succeeds; that is a new state of the video, not a retry. Every error response carries a `request_id`; include it when contacting support.
