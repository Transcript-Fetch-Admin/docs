<a id="sec-example-response" />

## Example response

```json
{
  "ok": false,
  "request_id": "req_…",
  "error": {
    "code": "upstream_unavailable",
    "message": "The transcript service could not be reached. Safe to retry."
  }
}
```

v1 failures carry `error.code` and `error.message` (plus `issues` on validation failures); transcript failures repeat the code as a top-level `reason` and add an `ai_fallback` hint.

<a id="sec-what-it-means" />

## What it means

The transcript service could not be reached. Safe to retry.

<a id="sec-why-it-happens" />

## Why it happens

- The transcript service behind the API was briefly unreachable.
- The idempotency store was unavailable, so a request with an Idempotency-Key was refused rather than risk double-billing (HTTP 503 in that case).

<a id="sec-what-to-do" />

## What to do

- Retry with exponential backoff; these are transient by nature.
- Check status at status.transcriptfetch.com if failures persist.

**Retryable?** Yes, safe to retry; failed requests are never charged. Every error response carries a `request_id`; include it when contacting support.
