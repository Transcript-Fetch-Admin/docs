## Example response

```json
{
  "ok": false,
  "request_id": "req_…",
  "error": {
    "code": "invalid_request",
    "message": "The batch exceeds your plan's per-request cap. error.details carries the cap and what was sent."
  }
}
```

v1 failures carry `error.code` and `error.message` (plus `issues` on validation failures); transcript failures repeat the code as a top-level `reason` and add an `ai_fallback` hint. **v1 never emits this code**; it answers `invalid_request` for this situation.

<a id="sec-what-it-means" />

## What it means

The batch exceeds your plan's per-request cap. error.details carries the cap and what was sent.

<a id="sec-why-it-happens" />

## Why it happens

- More video ids than your plan allows in one batch call. `error.details` carries `max` (your cap) and `sent`.

<a id="sec-what-to-do" />

## What to do

- Split the list into batches of at most `details.max`.
- Upgrade for a larger cap: 50 on the free tier, Basic and Pro; 500 on Mega and Scale.

**Retryable?** Only with a smaller batch. Nothing was fetched or charged. Every error response carries a `request_id`; include it when contacting support.
