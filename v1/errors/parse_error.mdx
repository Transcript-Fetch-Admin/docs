<a id="sec-example-response" />

## Example response

```json
{
  "ok": false,
  "request_id": "req_…",
  "reason": "parse_error",
  "error": {
    "code": "parse_error",
    "message": "Upstream returned a response that couldn't be parsed."
  }
}
```

v1 failures carry `error.code` and `error.message` (plus `issues` on validation failures); transcript failures repeat the code as a top-level `reason` and add an `ai_fallback` hint.

<a id="sec-what-it-means" />

## What it means

**Parse error.** Upstream returned a response that couldn't be parsed.

Shown to end users as: “We got an unexpected response fetching this video. Please try again.”

<a id="sec-why-it-happens" />

## Why it happens

- Parse error. Upstream returned a response that couldn't be parsed.
- Transient by definition: the same request may succeed a moment later.

<a id="sec-what-to-do" />

## What to do

- Transient failure. Wait the seconds in the Retry-After header when present, otherwise back off about 30 seconds, then retry the same request.
- Back off exponentially on repeats. Failed requests are never charged.

**Retryable?** Yes, after the Retry-After window (about 30 seconds when the header is absent), with exponential backoff on repeats. Every error response carries a `request_id`; include it when contacting support.
