## Example response

```json
{
  "ok": false,
  "request_id": "req_…",
  "error": {
    "code": "invalid_request",
    "message": "The body failed validation. error.issues names each field and constraint.",
    "issues": [
      {
        "path": [
          "video"
        ],
        "message": "Required"
      }
    ]
  }
}
```

v1 failures carry `error.code` and `error.message` (plus `issues` on validation failures); transcript failures repeat the code as a top-level `reason` and add an `ai_fallback` hint.

<a id="sec-what-it-means" />

## What it means

The body failed validation. error.issues names each field and constraint.

<a id="sec-why-it-happens" />

## Why it happens

- The JSON body is malformed or missing a required field (e.g. `video`, `channel`, `query`).
- A field has the wrong type: `limit` as a string, `video_ids` not an array.
- `limit` is out of range, or a single-video option (`mode`, `ai_fallback`) was sent to a list endpoint.

<a id="sec-what-to-do" />

## What to do

- Read the `error.issues` array in the response; it names the exact field and constraint that failed.
- Compare your body against the request example in the endpoint's docs page.
- Send `Content-Type: application/json` and valid JSON (no trailing commas).

**Retryable?** Only after correcting the body; the same body will fail the same way. Every error response carries a `request_id`; include it when contacting support.
