<a id="sec-example-response" />

## Example response

```json
{
  "ok": false,
  "request_id": "req_…",
  "error": {
    "code": "rate_limited",
    "message": "Your key's per-plan request rate was exceeded. Wait Retry-After seconds, then continue."
  }
}
```

v1 failures carry `error.code` and `error.message` (plus `issues` on validation failures); transcript failures repeat the code as a top-level `reason` and add an `ai_fallback` hint.

<a id="sec-what-it-means" />

## What it means

Your key's per-plan request rate was exceeded. Wait Retry-After seconds, then continue.

<a id="sec-why-it-happens" />

## Why it happens

- Too many requests per minute on one API key.
- A burst of concurrent calls (a parallel loop without throttling).

<a id="sec-what-to-do" />

## What to do

- Wait the number of seconds in the `Retry-After` response header, then retry.
- Add exponential backoff, or spread bulk work through the batch endpoint (many videos in one request = one rate-limit unit).

**Retryable?** Yes, after the Retry-After window. Back off exponentially on repeats. Every error response carries a `request_id`; include it when contacting support.
