<a id="sec-example-response" />

## Example response

```json
{
  "ok": false,
  "request_id": "req_…",
  "reason": "age_restricted",
  "error": {
    "code": "age_restricted",
    "message": "The video is age-restricted and not accessible without sign-in."
  }
}
```

v1 failures carry `error.code` and `error.message` (plus `issues` on validation failures); transcript failures repeat the code as a top-level `reason` and add an `ai_fallback` hint.

<a id="sec-what-it-means" />

## What it means

**Age-restricted.** The video is age-restricted and not accessible without sign-in.

Shown to end users as: “This video is age-restricted, so its transcript can't be fetched.”

<a id="sec-why-it-happens" />

## Why it happens

- Age-restricted. The video is age-restricted and not accessible without sign-in.

<a id="sec-what-to-do" />

## What to do

- Permanent for this input: the same request will fail the same way, so do not retry unchanged. Failed requests are never charged.
- The content likely contains speech even though no caption track can be served, so AI transcription of the audio may still produce a transcript. When it can, the response carries `error.retry_with: &#123; "mode": "audio" &#125;`; send that and it bills from 1 credit (1 credit per started minute of audio) on delivery, never on failure.

**Retryable?** No, this is permanent for this input. Every error response carries a `request_id`; include it when contacting support.
